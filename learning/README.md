# Jev 的上下文学习：把例子和记录放进 state，它能学到什么（实测）

> **证据等级：实测。** 2026-09-24 至 27，全部经 OpenRouter `POST /api/v1/systemone`，模型快照 `typesafe/jev-1.13-20260917`。分五轮做，各轮的数字分表给出，不混用：
> - **首轮**（09-24）：老虎机、猜规则、迷宫、国际象棋；
> - **补测**（09-24，也叫第二轮）：针对首轮的设计缺陷补做——干净的 few-shot 猜规则、老虎机拆开"怎么问"和"怎么选"、迷宫去掉距离干扰、小型 few-shot 分类；
> - **第三轮**（09-26）：迷宫纯导航对照与"已知坑当墙"；老虎机 8 钮与小差距两种难度、随机对照、拆开长期目标与探索提示；
> - **第四轮**（09-27）：迷宫把距离换成直线距离的对照，附零请求的纯程序基线；老虎机换新奖励种子，补"按时间表随机"对照、复测探索提示；
> - **第五轮**（09-27）：迷宫只删踩坑记录的对照。
>
> **请求量：** 首轮——老虎机与猜规则 6,660 次（约 $0.40），迷宫 8,621 次（$0.28），国际象棋 684 次（$0.21）。补测——猜规则 5,600 次（$0.23），老虎机 13,400 次（$0.68），迷宫 11,304 次（$0.36），few-shot 分类 1,100 次（$0.03）。第三轮——迷宫 10,866 次（$0.29），老虎机 56,000 次（$3.92）。第四轮——迷宫 8,188 次（含冒烟 9 局 226 次，冒烟局沿用进全量，$0.22），程序基线 0 次；老虎机 102,400 次（$5.27，每组 160 局，分三段跑到 80、120、160 局）。第五轮——迷宫 1,246 次（含冒烟 1 局，$0.036）。**这 12 个脚本合计约 226,070 次、约 $11.9，大头是第三、四轮的老虎机（158,400 次、$9.19）。** 不在脚本里的：首轮冒烟约 10 次、补测冒烟几十次、第三轮冒烟 5 次，另有一次误启动旧的国际象棋问法脚本、约 2 分钟后手动终止（估计几百次、几分钱，数据不用）。
> **起因：** 官方和社区都有"把经验喂给它、越玩越好"的说法（拆解见另一份文献整理，未收录本仓库），[打游戏实测](../games/README.md)只测过"把最近几步塞进 state 治不了打转"。这份报告问：把例子、游戏历史放进 state，Jev 能从里面学到什么，会不会自己"越玩越好"。
> **未覆盖：** 官方直连、其他快照；温度和别的抽样法；多特征规则、更大的迷宫、更多种棋局面。详见文末。
> **复现脚本（都在本目录）：** 首轮 `exp_icl_bandit.py`（老虎机固定历史 / 在线闭环 / 猜规则）、`exp_icl_maze.py`（带隐藏陷阱的多局迷宫）、`exp_icl_chess.py`（国际象棋错误记录）；补测 `exp_icl_rules.py`、`exp_icl_bandit2.py`、`exp_icl_maze2.py`、`exp_icl_fewshot.py`；第三轮 `exp_icl_maze3.py`、`exp_icl_bandit3.py`；第四轮 `exp_icl_maze4.py`、`exp_icl_bandit4.py`；第五轮 `exp_icl_maze5.py`。

## 怎么跑

```bash
export OPENROUTER_API_KEY="sk-or-v1-..."      # 或 API_KEY_OPENROUTER
python3 learning/exp_icl_fewshot.py run       # 发请求，断点续跑
python3 learning/exp_icl_fewshot.py report    # 只读日志，重出本文的表
```

- 每个脚本都是 `run` 发请求、`report` 只读日志出表。回包写在脚本旁边的 `icl_*_log.json`（已在 `.gitignore` 里排除，不入库），中断后再 `run` 会接着跑（`exp_icl_chess.py` 例外：它全部发完才写日志，中途中断会从头再发）。
- 用研究时的日志跑 `report`，重出的表与本文一致。
- 除 `exp_icl_chess.py` 外都只用标准库，Python 3.9 起。`exp_icl_chess.py` 要 `python3 -m pip install chess`，连 `report` 也要先设好 key（它会载入 `games/chess/exp_game_chess.py`，那个脚本一导入就要 key）；而且要先跑 `games/chess/exp_game_chess_prompt.py`：它从那份问法对比的日志里挑 Jev 送过子的局面。重跑问法对比时 Jev 的回答会有少许出入，挑出的局面就可能和本文的 38 个不同，第五节的数字未必能逐项对上。
- 迷宫每局会提前结束（到终点、踩坑或超时），请求数随回答浮动，重跑不会和本文的请求量分毫不差。
- 后几轮的脚本会 import 前几轮的同目录脚本，12 个文件放在一起别拆开。`exp_icl_maze4.py` 和 `exp_icl_maze5.py` 的 `report` 还会只读第三轮的日志（`icl_maze3_log.json`）做对照，没有它就出不了完整对照，先跑 `exp_icl_maze3.py`。
- 有几个脚本带小批量冒烟：`exp_icl_bandit2.py smoke`、`exp_icl_bandit4.py smoke [轮数]`（这两个不写日志）、`exp_icl_fewshot.py smoke`、`exp_icl_rules.py run --smoke`（只跑每族第 0 个任务，写进日志、全量时不重跑）；`exp_icl_rules.py show` 不发请求，只打印几个完整请求体。各脚本的分组子命令（如 `exp_icl_bandit3.py run SPLIT`）写在文件开头的说明里。
- `python3 learning/exp_icl_maze4.py baseline` 是零请求的纯程序对照（见第四节第四轮）。`exp_icl_bandit4.py run` 支持 `--max-run N`（只跑局号小于 N 的局）和 `--until HH:MM`（到点不再开新局），本文的数字是分三次扩到每组 160 局的结果。**复现本文请用 `python3 learning/exp_icl_bandit4.py run --max-run 200`**（局号 40–199，每组 160 局，共 102,400 次）；不加 `--max-run` 会跑满每组 200 局、128,000 次，`report` 也会把多出的局算进去。
- 最贵的是 `exp_icl_bandit4.py`（102,400 次、约 $5.3）和 `exp_icl_bandit3.py`（56,000 次、约 $3.9），其余每个几百到一万多次。

**术语。** 这份报告测的是**上下文学习**（in-context learning，ICL）：模型参数不变，只靠输入里的例子、资料、历史来调整输出。几个容易混的词：

- **上下文学习（ICL）**：参数不变，靠 state 里的例子 / 记录改变判断；本报告的 few-shot 分类、猜规则属于这类。
- **上下文强化学习**（in-context reinforcement learning）：ICL 里记录是"动作 + 奖励"的那一类，要从奖励反馈里摸出好动作；老虎机、多局迷宫属于这类。
- **测试时训练**（test-time training）：推理时真的更新参数；Jev 不这么做（官方说所有账号同一套权重），本报告也不涉及。
- **测试时计算**（test-time compute）：推理时多花算力（多想几步、多采样），说的是算得多，不是学。

"越玩越好"是社区的口语说法，本报告只在引号里用；说能力时用上面的名字。

## 先给结论

**Jev 能做上下文学习：不改参数，只靠这次输入里的例子和记录，就能把判断调准；能强多少，很大程度看怎么喂。** 这里的"变强"指判断变准，不等于多步任务自己通关。"把原始游戏日志堆进去，它就会自己越玩越好"不可靠。要拆成四件事分开说：

| 问题 | 判断 | 关键证据 |
|---|---|---|
| **读历史**：能不能从记录 / 例子里得出新判断 | **能，程度看写法。** 标签没有含义、只靠例子定义时，每类 1 个例子就从瞎猜拉到 85%；奖励记录够长时挑得出平均最高的按钮；猜规则在没见过的新牌上明显高于瞎猜（数字也没在历史里出现过的新牌同样如此）。 | few-shot 分类 23% → 85% → 97%；老虎机英文原始记录 128 轮 47/50；猜规则非箭头规则 64 条原始记录 63–69%（瞎猜 50%） |
| **归纳**：能不能从一条条对错里找出隐藏规则 | **学到一部分，分不清是不是归纳。** 没见过的新牌上明显好于瞎猜；醒目的规则（颜色、箭头）学得好，不显眼的（单双）接近瞎猜；把记录机械翻成"牌面→正确按键"后明显变好。成绩强弱顺序和"找最像的历史牌照抄"的最近邻程序一样，分不清是归纳出了规则还是按相似牌类推；一个在四个特征里挑最吻合那个的几行程序，16 条记录就四族全对。 | 非箭头三族：原始 64 条 95–104/150，翻成正确按键 127–130/150；只看数字没在历史里出现过的新牌，原始 69%、正确按键 82%；挑最吻合特征的程序 16 条 200/200 |
| **探索**：会不会主动试没试过的 | **每次只取最可能的那个动作时探索不足；按它给的概率抽样明显更好。** 4 钮时本批平均成绩接近 Thompson 基线；8 钮时两批都有用、幅度不一，离 Thompson 有明显差距。看起来 Jev 拿不准时，抽样会把机会分给别的按钮，拿得准时只押一个——这是描述，直接证据只在 4 钮，8 钮上没坐实。8 钮时"抽样胜过同量乱按"两批不一致，不作结论；照抄抽样试探时机的随机和均匀乱按一样，好处不能记在"前期多试"上。问句里加一句探索提示能让它多锁对最好的按钮，换新种子复测也成立；再告诉它总轮数，没有更好。 | 80 轮在线后段命中（4 钮）：取最高项 62%，按概率抽样 85%，只加探索提示再抽样 93%；Thompson 94%。8 钮两批：取最高项 35% / 37%、抽样 57% / 48%、Thompson 83% / 79%。同局配对：抽样比取最高项多 5.7 分（4 钮，1.9–9.5），8 钮两批 +5.45（0.5–10.4）、+2.8（0.6–5.0）。探索提示只取最高项：62% → 78%（40 局），新种子 60% → 76%（160 局锁对 96 → 121，32 局变好 7 局变差，p≈0.00007） |
| **绕路**：能不能先绕远再到终点 | **不给距离时，要绕的路越长越走不到；卡点是绕路，不是装不下、也不是记不住坑。** 没有陷阱、只给坐标和墙，一路朝终点就能到的起点九成走到，要比直走多绕 4 步以上的约四分之一；把两个坑画成看得见的墙，还是多半走不出来。给了正确距离就全部走到。它每步挑眼前看起来最好的方向：给它标成"离终点几步"的数，它就照这个数走；换成不管墙的直线距离，要绕路的地方就和只会挑最小数的程序一样栽。多局迷宫里"越玩越好"的是整套系统，出力最多的是程序（记坑、算路），见第四节。 | 纯导航按要绕的步数 0 / 2 / 4+：两组合计 82/90、37/55、25/95（只看没有陷阱那组 66/69、27/32、5/19）；坑画成墙 46/120；给正确距离 240/240；多局：第 1、2 局各踩一个坑，第 3 局起 72 局全通，纯程序照走输赢一模一样，删掉踩坑记录 60 局 |

**外部代码的贡献仍然很大**：把记录整理成统计表、替它把每个按钮试一遍、把距离按已知陷阱重算，都能把表现明显拉高（统计表 64 轮起 30/30；程序代按后在线后段 0.85；重算距离后迷宫 38/120，把已知陷阱当墙算后 72/120）。但也不能说"学习全在适配器"：原始记录本身也改善了多项任务，只是改善得不稳、受写法和取动作方式影响很大。

**对应用的意义：** 想让它在游戏里"越玩越好"，(1) 记录别直接堆一轮一行的原始日志：猜规则里机械翻成"情况→正确做法"效果最好，老虎机里按选项分组列得分效果好（但分组写法在猜规则的长记录里反而更差，要按任务试）；(2) 需要探索的场景按 `probabilities` 抽样，别只取 `choice`，问句里可以明说"没试过的也可能更好"；(3) 需要绕路的任务，距离、路线在适配器里算好更稳。

## 一、多臂老虎机：会读账本；探索不足来自"只取最高项"

**设计。** 4 个按钮 A–D，最好的中奖概率 0.75、其余 0.25，题面不说哪个最好。历史由程序随机生成，放进 state 问"下一轮按哪个"。

### 首轮：固定历史（`exp_icl_bandit.py` A 部分）

两种历史：`uniform` 每轮等概率随机按（按得多少不含信息）；`mislead` 偏爱某个差按钮（按得最多、总分也最高的是差按钮，平均分最高的才是好按钮）。**`mislead` 实际约 70% 的轮次按偏爱的差按钮**（脚本先以 0.6 选它，否则从全部四个里随机，0.6 + 0.4/4 = 0.7；脚本说明里写的"六成"是标称值）。写法：只有动作 / 原始一轮一行（含得分）/ JSON 列表 / 程序算好的每按钮次数与平均分 / 程序写一句"目前 X 平均最高" / 直接告诉答案 / 不给历史。每格 30 题，最好按钮每题随机（没有均衡）。

**选中真最好（每格 n=30，瞎猜约 7/30）：**

| 历史长度 | 4 | 8 | 16 | 32 | 64 | 128 | 256 | 1,600 |
|---|---|---|---|---|---|---|---|---|
| uniform 原始一行一轮 | 15 | 16 | 21 | 22 | **30** | 28 | 30 | 30 |
| uniform 程序算好的统计表 | 17 | 16 | 22 | 28 | 30 | 30 | 30 | — |
| mislead 原始一行一轮 | 11 | 8 | 10 | 19 | 23 | 21 | 20 | 21 |
| mislead JSON | 11 | 7 | 9 | 17 | 19 | 18 | 19 | — |
| mislead 程序算好的统计表 | 8 | 13 | 16 | 26 | **30** | 30 | 30 | — |
| 只有动作、不写得分（mislead） | 1 | 1 | 0 | 0 | 0 | 0 | 0 | — |

基线：不给历史 7/30（天然偏爱 A）；直接告诉答案 30/30。"一句话经验"与统计表几乎一样。

- **原始记录它读得懂，信号干净时 64 轮起基本全对**：uniform 64、256、512、1,024、1,600 轮都是 30/30，128 轮 28/30；JSON 在 64、128 轮是 29/30。
- **频率和平均分打架时，中文原问法下原始记录卡在约七成**：mislead 32 轮以上 210 题里 149 题选平均最高、66 题选总分最高（两者只有 7 题重合；总分并列时只算字母最靠前的那个，若并列都算中则是 70 题、11 题重合），64 → 1,600 轮不再涨。程序把平均分算好，64 轮起 30/30。在这批偏置历史和中文原问法下，64–1,600 条原始记录没有呈现继续改善的趋势；补测显示换问法和写法能修好大半，见下。
- 只写动作不写得分时，它就照抄按得最多的那个（mislead 32 轮起 30/30 选了差按钮）。

### 补测：固定历史诊断（`exp_icl_bandit2.py` FIX 部分，频率偏置改成准确的 60%）

`mislead` 改成每轮 60% 按偏爱的差按钮、40% 从其余三个里随机；最好按钮在题间均衡；每格 50 题。

| 写法 | 中文 32 轮 | 中文 128 轮 | 英文 32 轮 | 英文 128 轮 |
|---|---|---|---|---|
| 原始一行一轮 + 原问法 | 33 | 39 | 33 | **47** |
| 原始 + 问句加"比较平均分，别看次数和总分" | 35 | **48** | — | — |
| 按按钮分组列原始得分（A：1,0,0,1…，不算平均） | 41 | **49** | 38 | **50** |
| 程序算好的统计表 | 43 | 50 | — | — |

- **不替它算数，只改怎么问、怎么排，原始记录也能追上统计表**：128 轮时加一句"比较平均分"48/50，按按钮分组 49/50（英文 50/50）。由此看，首轮"原始记录卡在七成"很大程度是写法和问法的问题，不是读不懂；但两轮偏置强度不同（首轮 70%、补测 60%），首轮的 70% 条件没有用新写法重测。
- **中英文只在一格看到明显差别**：128 轮原始记录、原问法，英文 50 题对 47，同样的记录换成中文对 39；按题配对只有英文答对的 8 题、只有中文答对的 0 题（p≈0.008），这一格中文确实更差。32 轮两者都是 33/50，分组写法 32 轮中文反而多 3 题，其他格子没有一致的方向。

### 首轮：在线闭环 40 轮（`exp_icl_bandit.py` B 部分）

Jev 自己玩 40 轮，每轮把自己的记录放进下一轮，动作取回包的 `choice`（实测都等于概率最高项）；20 局，同一组随机种子。每 10 轮一段选中真最好的比例：

| 策略 | 1–10 | 11–20 | 21–30 | 31–40 |
|---|---|---|---|---|
| Jev，原始记录 | 0.49 | 0.55 | 0.55 | 0.55 |
| Jev，统计表 | 0.35 | 0.35 | 0.35 | 0.35 |
| Jev，原始记录，前 8 轮由程序代按（每钮两次） | 0.34* | **0.84** | 0.85 | 0.85 |
| Jev，统计表，前 8 轮程序代按 | 0.35* | 0.82 | 0.85 | 0.85 |
| 随机 | 0.26 | 0.30 | 0.19 | 0.26 |
| 贪心（先每个试一次，之后按平均最高） | 0.45 | 0.81 | 0.85 | 0.85 |
| UCB1 | 0.34 | 0.48 | 0.61 | 0.62 |

（*含程序代按的 8 轮。）

- **统计表组 20 局全程只按 A**，哪怕 A 平均只有 0.2、其余三个一次都没试过；这 20 局里恰有 7 局最好的就是 A，所以"始终按 A"本身就能拿到 0.35。
- **原始记录组不是零探索**：20 局里 15 局试过不止一个按钮，全部对局共换了 33 次按钮，第 1 轮选中真最好 7/20、第 40 轮 11/20。准确说法是"早期有少量尝试，随后锁定"。
- 程序替它把每个按钮试两次后，它和"先每个试一次"的贪心在后段都是 0.85；这只说明后段命中率一样，不代表行为完全相同，贪心基线自带启动探索，差距不能全算在读经验上。

### 补测：把"怎么问"和"怎么选"拆开（`exp_icl_bandit2.py` ONLINE 部分，80 轮 × 40 局）

两种问法 × 两种取动作方式，记录统一用原始一行一轮；40 局最好按钮均衡（A–D 各 10 局），四组和本地基线共用同一份奖励。问法 `long` 在原问法上点明"一共 80 轮、现在第 t 轮、还剩几轮，目标是总分最高"，同时还写了"前期适当尝试、摸清各按钮再集中按最好的"这类探索提示，所以下文叫它**长期目标 + 探索提示**：它测的是两者合在一起的作用。取动作：`argmax` 用回包 `choice`，`sample` 按 `probabilities` 抽。

- **只取最高项时停在 62%，按它给的概率抽样就不再锁死**：后段命中 62% → 85%，总分 44.5 → 50.2（同局配对多 5.7 分，区间不含 0），本批平均成绩接近"先每个试一次"的贪心和 Thompson 基线；这只说明本批 40 局差不多，不等于证明了同等水平（和 Thompson 的配对差区间约 −6 到 +3）。抽样时所选项平均概率仍有 0.94，说明分布大多很尖，但剩下那点不确定性足够带来有效探索。这 5.7 分不是每局都多一点：40 局里 13 局变好、14 局变差、13 局持平，均值靠几局"只取最高项锁死在差按钮、抽样把它救回来"的大幅差撑起来；变好的总幅度远大于变差的，按局置换检验 p≈0.004。准确的读法是抽样救回了会锁死在差按钮上的那几局，不是普遍更好。
- **只取最高项时它也不是最差的**：总分 44.5，高于"不先试的贪心"（35.2）和始终按 A（31.1），和 UCB1 相当（43.6）；但后段停在 62%。

- 第 1 轮回包的首选项都是 A：三组 40/40 按 A，加提示且抽样的那组抽到 A 38 局、C、D 各 1 局。这是没有信息时的位置 / 字母偏好。
- 归因要分清：抽样后的提升是"Jev 的概率 + 抽样规则"这个系统的收益，抽样规则是外部代码；这些概率也不是贝叶斯后验，不能当 Thompson 用的后验看。

**文献旁证。** Krishnamurthy、Harris、Foster、Zhang、Slivkins 的 [Can Large Language Models Explore In-Context?](https://arxiv.org/abs/2403.15371)（2024，NeurIPS 2024）在老虎机上测 GPT-3.5、GPT-4、Llama2：只给原始交互历史时都不能稳定探索，典型失败是开头几轮之后再也不按最好的那个（论文叫 suffix failure）；所有配置里只有一组像样——GPT-4 + 外部把历史汇总成每个按钮的次数与平均分 + 思维链 + 提示要兼顾探索，温度 0。和这里同向的是：原始记录不稳、程序算好的统计表更稳；"只取最高项"后段停在 62% 也像它说的 suffix failure。差异在于：它测的是生成式 LLM、靠提示词和思维链，温度 1 采样的配置也没能稳定探索；这里测的是 Jev（不生成推理过程），按回包概率抽样后 4 钮时本批平均成绩接近 Thompson 基线。论文试过同样的做法：让 GPT-4 返回一个概率分布、由外部抽样，结果是各按钮按得差不多均匀、淘汰不掉差按钮的另一种失败；Jev 按概率抽却接近基线，这个反差值得记，原因没验证（可能是 Jev 的概率更尖，也可能只是任务不同，论文用 5 钮、中奖率差 0.2）。按按钮分组列原始得分也能追上统计表，这一条论文里没有对应项（它的历史只有原始和汇总两种）。

### 第三轮：随机对照、更难的两种设置、拆开长期目标与探索提示（`exp_icl_bandit3.py`）

全部在线闭环、原始一行一轮记录、每组 40 局。三件事：

1. **SPLIT**（同上一节设置，4 钮 0.75/0.25、80 轮，奖励与上一节同局号共用 → 可逐局配对）：问句只加"一共 80 轮、现在第 t 轮、目标 80 轮总分最高"（下称**长期目标**），或只加"没试过或试得少的按钮也可能更好，前期适当尝试……"（下称**探索提示**），各配取最高项 / 按概率抽；另加两组随机对照：**ε 随机**（原问法取最高项，但每轮 5% 概率改成四个里随便按一个；上一节抽样组实际偏离最高项的轮次 3.6%（116/3200），ε=0.05 时 3.75%，随机量对齐）和 **均摊**（每轮以最高项自己的概率选它，剩下的概率在其它按钮间均分，和抽样只差在"非最高项之间怎么排"）。
2. **H8**：8 个按钮，最好 0.75、其余 0.25，80 轮：原问法取最高项 / 按概率抽 / ε 随机 / 均摊。
3. **GAP**：4 个按钮，最好 0.6、其余 0.5，200 轮：同上三组。

本地基线用同一份奖励（与上一节的基线换了随机种子与并列时的抽法，数值略有出入，如 Thompson 80 轮总分 52.3 对 51.8；先试贪心 54.0 对 52.0，同一份奖励只差在并列时怎么抽签，基线自己就有约 2 分的波动）。

全部换新奖励种子（局号 40–199，和前几轮的 0–39 不重叠，每组 160 局，最好按钮按局号轮换；分三段跑到 80、120、160 局，以 160 局为准），同一实验内各组共用同一份奖励、逐局配对；原始一行一轮记录，问句与第三轮逐字一致。

- **照抄试探时机的随机没多拿分；8 钮上局面信号没坐实**：按时间表随机照抄了离开首选的时机（而且更集中在前 20 轮，55%），命中 40.5%，和 ε 随机（42.4%）一样（−0.8，−3.4 到 1.8），照抄时机的前期试探贡献约为 0，所以好处不能记在"前期多试"上。抽样、均摊比它多 2.7、3.0 分，区间都擦着 0；而且均摊组实际离开首选 6.1% 的轮次、时间表组 4.0%，每局多试约 1.7 次，这点差不能全算在局面信号上。先跑完的 80 局里这两条一度是 +5.0、+4.9 且不含 0，扩到 120、160 局后跨 0，以 160 局为准。
- 抽样和均摊几乎一样（−0.3），次高几项的排序仍没带来额外好处；抽样离 Thompson 仍远（48% 对 79%，−5.2 分）。

## 二、猜规则卡牌：能学到一部分，写法决定上限

**设计。** 牌有颜色（红/蓝）、数字（1–99）、箭头（朝左/右），按左或右键；隐藏规则一条。历史里的按键是随机按的，写对错。

### 首轮（`exp_icl_bandit.py` C 部分）

四种规则各一个方向（颜色、≥50、单双、"箭头朝哪边就按反方向"），当前牌放在历史前面，不同历史长度各自重新生成任务和测试牌，每格 30 题，瞎猜 15/30。

| 规则 | 不给历史 | 原始 4 / 16 / 64 轮 | 程序按每个特征统计对错 4 / 16 / 64 轮 | 告诉规则 |
|---|---|---|---|---|
| 颜色 | 22 | 23 / 18 / 18 | 22 / 26 / **30** | 30 |
| ≥50 | 20 | 14 / 19 / 18 | 22 / 28 / 29 | 30 |
| 单双 | 10 | 14 / 17 / 16 | 18 / 25 / 28 | 30 |
| 箭头反向 | **0** | 20 / 23 / 23 | 28 / 30 / 30 | 30 |

- 不给历史时四种规则全部顺着箭头按，所以"不给历史"的数字其实是测试牌上"顺箭头恰好对"的比例，各长度之间也不能直接相减（颜色规则不给历史 22/30、32 条记录 18/30，后者同一批题"永远顺箭头"只能得 11/30）。首轮这张表混着顺箭头的偏差，补测控制了它，以补测为准。
- 箭头反向规则 16 条原始记录后 23/30，这 30 张测试牌没有一张在各自历史里原样出现过：这已经是跨样例的有限适应，只是分不清是归纳出了规则还是按相似特征匹配。
- 程序按特征统计后接近满分；但这张表不只是"替它数数"，还替它挑好了候选特征、把随机按键还原成了正确按键。

### 补测：干净的 few-shot（`exp_icl_rules.py`）

- 规则 4 族 × 正反两个方向（如"红→左"和"红→右"、顺箭头和逆箭头），每族 50 个任务、正反各半。
- 每个任务一条 64 张牌的历史序列和一张测试牌；4 / 16 / 64 条取**同一序列的前缀**，测试牌不变，且和这 64 张都不重复（颜色、数字、箭头不全同）。
- 测试牌在族内平衡：正确答案左右各半；非箭头规则里"正确答案恰好等于箭头方向"的占一半，顺箭头蒙不出分。
- 选项顺序随机，历史放在当前牌前面，中英文用同一批任务各做一遍。
- 写法四种：原始（随机按键 + 对错）；原始 + 明确指令（"按键是随机的，别模仿，只看对错，先推断规则"）；**正确按键**（每条机械翻成"牌面 → 该按哪边"，不做统计）；**分组**（"按左才对的牌：…；按右才对的牌：…"）。

**非箭头三族合计（颜色 + ≥50 + 单双，每格 n=150，瞎猜 75）：**

| 写法 | 中文 4 / 16 / 64 条 | 英文 4 / 16 / 64 条 |
|---|---|---|
| 不给历史 | 75 | 75 |
| 原始 | 71 / 94 / 95 | 72 / 94 / 104 |
| 原始 + 明确指令 | 68 / 100 / 97 | 73 / 100 / 106 |
| 正确按键 | 87 / 114 / **130** | 87 / 115 / **127** |
| 分组 | 94 / 103 / 87 | 95 / 103 / 87 |
| 告诉规则 | 150 | 150 |

**分族看（每格 n=50，瞎猜 25；中文 / 英文）：**

| 规则族 | 原始 64 条 | 正确按键 64 条 | 分组 64 条 |
|---|---|---|---|
| 颜色 | 42 / 42 | 50 / 50 | 33 / 31 |
| ≥50 | 31 / 35 | 44 / 45 | 28 / 30 |
| 单双 | 22 / 27 | 36 / 32 | 26 / 26 |
| 箭头（顺、逆各半） | 50 / 50 | 49 / 50 | 41 / 40 |

- **原始对错记录也能学到一部分**：给 64 条随机按键的对错记录，非箭头三族在没见过的新牌上中文 95/150（63%）、英文 104/150（69%），区间都在瞎猜之上；颜色规则 42/50。
- **规则越不显眼越难**：颜色 > ≥50 > 单双；单双用原始记录 64 条仍接近瞎猜（22–27/50），4 条时甚至低于瞎猜（14–15/50）。
- **机械翻成"牌面→正确按键"帮助最大**：64 条时 127–130/150（85–87%，即中文 63% → 87%、英文 69% → 85%），颜色 50/50。说明"随机按键 + 对错"多出来的那一步反推，是原始记录吃亏的主要原因之一；这一步不涉及归纳，适配器顺手就能做。但测试牌只保证颜色、数字、箭头不全同，数字本身可能在历史里出现过，有一部分提升来自照抄同数字的那条记录（单双那格尤其如此）。
- **只看数字没在历史里出现过的新牌**（中英合计）：非箭头三族原始写法 122/176（69%）、正确按键 144/176（82%），仍明显好于瞎猜，翻成正确按键也仍然更好；全部题分别是 66% 和 86%。这部分主要来自颜色和 ≥50。
- **分不清是归纳还是类推**：成绩的强弱顺序（颜色 > ≥50 > 单双）和"按牌面找最像的历史牌照抄"的最近邻程序一样（最近邻 1 张：颜色、≥50 都是 50/50，单双 22/50）。真在"归纳"的最简单程序——在颜色、大小、单双、箭头四个特征里挑最能解释对错的那个，再多数票——16 条记录就四族全对（200/200）。Jev 64 条原始 63–69%、正确按键 85–87%，离这个差得远。（这三条是按现有日志离线算的，没发新请求。）
- **加一句"按键是随机的、先推断规则"几乎没用**（和原始记录差 0–6 题）。
- **分组写法到 64 条反而变差**：非箭头三族中英文都是 94–95 → 103 → 87，先升后降；64 条时顺箭头比例中文 106/150、英文 92/150，长列表里它更容易退回"顺箭头"的先验。原因没拆清。
- 箭头规则原始记录 64 条中英文都是 50/50；逆箭头比顺箭头难（有历史的各写法汇总 526/600 对 573/600；不给历史、直接告知规则两格不计入），但也学得会。
- 中英文差别不稳定：原始 64 条、原始加指令 64 条英文各多 9 题，正确按键和分组两种写法中英接近。

## 三、few-shot 分类：给例子就会用（`exp_icl_fewshot.py`，补测）

对应社区 JevGraph 作者报告的"五分类、每类一个带标签示例、500 条 85.6%"（作者报告，未独立复核）。这里自己写了 5 类英文短句（体育 / 财经 / 科技 / 美食 / 旅行），每类 20 条测试、8 条示例池；标签分两种：**有名字**（选项就叫 Sports 等）和**无含义**（选项叫 L1–L5，哪个 L 是哪类只在例子里出现，每句一个随机对应）。每格 100 句，瞎猜 20%。

| 每类例子数 | 0 | 1 | 2 | 4 |
|---|---|---|---|---|
| 有名字的标签 | 100 | 100 | 100 | 100 |
| 无含义标签，例子放 state | 23 | **85** | 92 | 97 |
| 无含义标签，例子写进选项描述 | — | 91 | 94 | 99 |

- **标签没有含义时，每类 1 个例子就从瞎猜拉到 85%**，和社区报告的 85.6% 巧合地接近；不给例子 23%（瞎猜 20%），每类 1、2、4 个例子分别 85%、92%、97%。这是标准的上下文学习：答案信息只在例子里，它读了例子并用到新句子上。这里 1、2、4 例是分别抽的例子，不是同一串例子逐条加长，只能说这三档依次升高，和 GPT-3 论文（Brown et al. 2020，[Language Models are Few-Shot Learners](https://arxiv.org/abs/2005.14165)）里 0 / 1 / 少量例子逐级变好同向；这里只测到每类 4 个，更多例子会怎样没测（[Many-Shot In-Context Learning](https://arxiv.org/abs/2404.11018)，Agarwal et al. 2024，在别的模型上看到有的任务继续涨、有的饱和或下降）。
- 有名字的标签不需要例子，任务本身太简单，看不出例子的作用。
- 例子写进对应选项的描述比单独列在 state 里略好（1 例时 91 对 85），差距在区间内，不算稳。
- 这只说明常规 few-shot 分类可用，不能直接推出"游戏里越玩越好"：游戏记录要先从动作和结果里反推"什么是对的"，比这一步难。

## 四、带隐藏陷阱的迷宫：卡在要先绕远的路，不是装不下、也不是记不住坑

### 首轮（`exp_icl_maze.py`）

**设计。** 6×6，墙可见，两个陷阱看不见（state 里显示成空地），踩到本局失败；陷阱卡在最短路上——绕开第一个，新的最短路上又卡着第二个，两个都绕开才能到。每步适配器给四个方向的目标格、类型、"走过去离终点几步"和来过几次（沿用[打游戏实测 GridWorld](../games/README.md#一gridworld状态怎么给决定它会不会玩)里 10/12 通关的写法）。**这个距离只按墙算、不管已知陷阱**（只有 plan 组按已知陷阱重算），字段名却叫"走过去后离终点几步"，没有注明。每轮连打 5 局，8 张图 × 3 次 = 每格 24 轮、120 局，步数上限 24：

| 跨局写法 | 谁在整理经验 | 第 1–5 局成功 | 合计 | 重踩已知陷阱（第 2 局起） | 超时 |
|---|---|---|---|---|---|
| none 不给 | — | 0,0,0,0,0 | 0/120 | 96/96 | 0 |
| raw 前几局完整轨迹 | Jev 读原始记录 | 0,0,0,0,0 | 0/120 | 65/96 | 16 |
| reason 只写"第 k 局在 (r,c) 踩到陷阱" | Jev 读环境反馈 | 0,0,1,0,0 | 1/120 | 24/96 | 57 |
| lesson 程序写"(r,c)、(r,c) 有陷阱，别走" | 程序汇总，Jev 对坐标 | 0,0,0,0,0 | 0/120 | 41/96 | 43 |
| mark 程序把陷阱标到方向上 | 程序标注 | 0,0,0,0,0 | 0/120 | **0**/96 | 84 |
| plan 标注 + 按避开陷阱重算距离 | 全由程序 | 0,0,**21,21,20** | 62/120 | 8/96 | 2 |

（陷阱要踩过才知道，第 1、2 局实际都没通关；但地图有安全绕路，8 张图的安全最短路 10–15 步，都在 24 步以内，不是躲不开。）

- **跨局记录被用上了**：已知陷阱就在隔壁时往那边走的步数比例，不给 96/96、原始轨迹 65/371、失败原因 24/798、程序汇总 41/560、程序标注 0/1,095。步数口径会重复计同一个坑边，不能当整局安全率；按局只算第一次遇到已知陷阱的机会，失败原因组只有 3/93 踩进去。
- 避开坑后，距离提示仍把它往坑边引，它在坑前打转直到超时。**这个失败混着两件事**：找不出绕路，和一个持续误导的距离字段。补测把它们拆开。

### 补测：去掉距离干扰（`exp_icl_maze2.py`）

12 张新图（种子 100–111，安全最短路 9–17 步）× 2 次，每次连打 5 局，**步数上限放宽到 40**。历史统一用"失败原因"写法（第 k 局在 (r,c) 踩到陷阱 / 走了 40 步超时），邻格一律不标 trap；只改距离字段：

- 原距离：只按墙算（同首轮）
- 原距离 + 注明：state 里写一句"距离按墙计算，没有考虑陷阱，可能穿过已知陷阱"
- 不给距离：其余字段都在（邻格类型、来过几次、终点坐标、墙列表）
- 重算距离：每个邻格的距离按"避开其它已知陷阱"算；陷阱格自己仍显示它到终点的真实步数，不标成走不通，躲它仍要靠记录

| 条件 | 第 1–5 局成功（各 /24） | 合计 /120 | 第 2 局起重踩已知陷阱 /96 | 超时 | 第一次再遇到已知陷阱就避开 |
|---|---|---|---|---|---|
| 不给历史 · 原距离 | 0,0,0,0,0 | 0 | 96 | 0 | 5/96 |
| 不给历史 · 不给距离 | 0,0,0,0,0 | 0 | 85 | 10 | 9/85 |
| 失败历史 · 原距离 | 0,0,2,0,3 | 5 | 30 | 48 | 85/96 |
| 失败历史 · 原距离 + 注明 | 0,0,1,1,2 | 4 | 20 | 59 | 92/96 |
| 失败历史 · 不给距离 | 0,2,0,2,0 | 4 | 15 | 70 | 74/83 |
| 失败历史 · 重算距离 | 0,0,**19**,10,9 | **38** | 33 | 1 | 56/83 |

（"第一次再遇到"按局计：第 2 局起，每局第一次站到已知陷阱隔壁时有没有避开，分母是出现过这种机会的局数。）

- **第一次再遇到已知的坑，约九成会避开**：失败历史的前三组 85/96、92/96、74/83；不给历史只有 5%–11%。这是模型自己读环境反馈、把坐标对到方向上，没有外部代码替它标注。这只算第一次那一刻；按整局算，这三组第 2 局起仍有 15–30 次（/96）重踩。
- **去掉误导的距离，通关也没起来**：不给距离时 4/120 通关、70 局超时；加一句"距离没考虑陷阱"也只有 4/120。首轮的失败不主要来自这个距离字段：拿掉它，Jev 避开了坑，却在几个格子间来回打转到超时（超时局 40 步里走到过的不同格子中位只有 5 个，不算起点；算上起点是 6 个）。当时还分不开"找不出绕路"和"没有距离就不会导航"，第三轮的纯导航对照分开了：主要是前者，见下。
- **只有把距离按已知陷阱重算，才开始通关**：第 3 局 19/24，全部 38/120、超时只 1 局。但这组重踩已知陷阱反而最多（33/96）：陷阱格上显示的是适配器把它当空地算出的距离，往往是几个方向里最小的——196 次站在已知陷阱隔壁的机会里，136 次陷阱方向距离等于最小值（81 次严格最小），而实际走进已知陷阱的 33 次全都选的是距离最小的那个陷阱方向。这支持"短距离把它吸过去"的解释，但不能证明失败全由此造成；这组也不是完全消除误导后的对照。
- 重算距离组第 3 局 19/24 之后第 4、5 局掉到 10、9，原因没拆清（成功那局在历史里只记一句"走到终点"，此后坑边的短距离又占了上风，这是推测）。
- 第 1 局所有条件都没通关（不给距离时 2 局超时、其余全踩坑）：第一次不知道坑在哪，陷阱又卡在最短路上。
- 归结：在这套输入和取动作方式下，记住坑不足以稳定通关，删掉距离提示也没解决；要稳定通关，目前靠适配器替它算路（重算距离、把坑标出来）。首轮 plan 组（标注 + 重算）62/120，比这里只重算的 38/120 高，提示"把坑直接标出来"可能也有贡献；但两轮的地图、步数上限、历史写法都不同，没在同一条件下对照。

### 第三轮：纯导航对照，和"已知坑当墙"的干净版（`exp_icl_maze3.py`）

补测没回答的一问：不给距离时通关起不来，是"找不出绕路"，还是"没有距离就根本不会按坐标走"？用补测同一批 12 张图（种子 100–111），步数上限 40，取动作仍是回包 `choice`。单局导航每张图取 10 个起点（原起点 + 9 个离终点至少 6 步的随机空格；这个 6 步按陷阱当墙算，去掉陷阱后有的起点真实最短路只有 3 步），5 个条件共用同一批起点，每格 120 局；Jev 对同一 state 选的方向基本不变（概率有抖动），所以用多起点而不是重复跑。

| 条件（单局，无历史） | 通关 /120 | 原起点 /12 | 超时 |
|---|---|---|---|
| 没有陷阱，不给距离（目标只写"走到终点"） | **98** | 10 | 22 |
| 同上，但目标沿用原来那句"有看不见的陷阱……" | 88 | 9 | 32 |
| 没有陷阱，给按墙算的距离 | 120 | 12 | 0 |
| 两个陷阱改成看得见的墙，不给距离 | **46** | 5 | 74 |
| 同上，给正确距离 | 120 | 12 | 0 |

按"必须多绕几步"分组（绕路步数 = 真实最短路比起点到终点的横竖格数多几步；0 表示一路朝终点走就行）：

| 不给距离 | 绕 0 步 | 绕 2 步 | 绕 4 步以上 |
|---|---|---|---|
| 没有陷阱 | 66/69 | 27/32 | 5/19 |
| 陷阱画成墙 | 16/21 | 10/23 | 20/76 |
| 两组合计 | **82/90（91%）** | **37/55（67%）** | **25/95（26%）** |

- **只靠坐标和墙，它会走迷宫**：没有陷阱、不给距离，98/120 走到终点，走到的局多数是最短路（多走步数中位 0）。所以补测里"不给距离就打转"不是不会按坐标导航。
- **卡在要先绕远的路**：要多绕的步数越多，越走不到（91% → 67% → 26%）。把陷阱直接画成看得见的墙，不用记也不用猜，还是多半走不出来（120 局走到 46 局，原起点 5/12）——和有失败历史、不给距离的 4/120 是同一个毛病（两组目标文字不同：画成墙那组没提陷阱，补测那组提了）：障碍在哪它知道，但要先背离终点走几步的路线它找不出来，常在障碍前几格来回转（超时局到过的不同格子中位 8 个，含起点）。
- **给了正确距离就全到**：有没有障碍都是 120/120。这时它只需每步挑距离最小的邻格，不用往前看。
- "提防陷阱"这句话本身有副作用：地图里其实没陷阱、目标里提了陷阱，通关 98 → 88、超时 22 → 32；按起点配对是 10:0（p≈0.002），集中在 4 张图上。
- **多局里程序把已知陷阱当墙算距离（陷阱格显示走不通，邻格类型仍不标 trap）**：失败历史写法不变。坑看不见、又卡在最短路上，照步数走，第 1、2 局都各踩了一个（48 个踩坑步全是当时距离最小的方向；地图有安全绕路）；第 3–5 局 **72/72 通关**，第 2 局起重踩已知陷阱 0/96，合计 72/120，超时 0。补测"重算距离"组只有 38/120，缺口来自陷阱格上仍显示真实步数、把它吸过去（见上）。首轮 plan 组（标 trap + 重算）62/120 是另一批图、24 步上限，不直接比。
- **这回越玩越好的是整套系统，出力最多的是程序**：记坑、算路交给程序——坑记在程序的列表里，程序把它当墙重新算好每个方向离终点几步，踩过的那格直接显示走不通。Jev 第 3–5 局 1,003 步里 95% 选的是距离最小的方向，一步也没往走不通的方向走。换成只会挑最小步数的程序来走，120 局输赢一模一样（第四轮末条）；Jev 读踩坑记录也有一点功劳：删掉记录、其余不变，通关从 72 局掉到 60 局（第五轮）。所以不能讲成 Jev 边玩边学到通关。
- **输入不大**：迷宫每步请求输入中位约 770 token、最多 880 token（来自补测日志，第三轮日志没记输入 token），远没到上下文上限，卡点不是装不下。
- **怎么解释（推断）**：Jev 每步直接给出各选项的概率，不写推理。"先往远处走、再绕回来"要往前看好几步；给了距离，这几步由程序算好，它只需挑最近的一格，于是全到。在这套迷宫里，它表现得像只凭直觉、不往前推几步。但绕 4 步以上的失败集中在三张图（没有陷阱那组这一档 14 次失败全在种子 100、102、108，种子 108 十个起点全失败），"要绕的路越长越容易失败"站得住，"主因是不做多步推演"仍只是推断；内部结构也没公开，没排除别的原因（比如对坐标的空间推理本身弱）。这里没有拿别的模型做同题对照。
- 请求量 10,866 次，$0.29。

### 第四轮：把距离换成"直线距离"的对照（`exp_icl_maze4.py`）

第三轮留下的解释是"每步挑眼前看起来最好的，眼前最好和真正最好一致才走得通"。这一轮做受控对照：复用第三轮的 12 张图、每图 10 个起点、步数上限 40、问法和 state 其余字段，只把距离字段换成**直线距离**（横竖格数之和，不管墙和坑），每格 120 局，取动作仍是回包 `choice`。三个新条件：

- 直线距离·字段名不变：仍叫"走过去后离终点几步"，数值换成直线距离（和第三轮"给正确距离"组只差数值）；
- 直线距离·如实命名：字段改叫"不考虑墙的直线距离"；
- 坑画成墙 + 直线距离·字段名不变。

另做了零请求的纯程序基线（`baseline` 子命令）：把 Jev 换成"每步走所给距离最小的可走方向"，并列时按方向顺序打破，四个方向的 24 种顺序全遍历；另一版并列时先挑来过次数少的（相当于也读"来过几次"）。绕路档位同第三轮（真实最短路比直线距离多几步）。

| 条件 | 通关 /120 | 绕 0 步 | 绕 2 步 | 绕 4 步以上 |
|---|---|---|---|---|
| 无坑·不给距离（第三轮） | 98 | 66/69 | 27/32 | 5/19 |
| 无坑·正确距离（第三轮） | 120 | 69/69 | 32/32 | 19/19 |
| **无坑·直线距离，字段名不变** | **80** | 60/69 | **19/32** | **1/19** |
| 无坑·直线距离，如实命名 | 98 | 66/69 | 28/32 | 4/19 |
| 纯程序挑直线距离最小（并列先挑来过少的；24 种顺序合计 /2880） | 2080（单一顺序 82–94/120） | 1488/1656 | 544/768 | 48/456 |
| 纯程序挑直线距离最小（只按方向顺序；/2880） | 1221（36–69） | 1056/1656 | 158/768 | 7/456 |
| 坑成墙·不给距离（第三轮） | 46 | 16/21 | 10/23 | 20/76 |
| 坑成墙·正确距离（第三轮） | 120 | 21/21 | 23/23 | 76/76 |
| **坑成墙·直线距离，字段名不变** | **20** | 10/21 | 7/23 | **3/76** |
| 纯程序（并列先挑来过少的；/2880） | 684（18–39） | 264/504 | 288/552 | 132/1824 |
| 纯程序（只按方向顺序；/2880） | 324（6–21） | 252/504 | 69/552 | 3/1824 |

纯程序按正确距离挑最小，两种并列规则、24 种顺序都是 120/120，和 Jev 给正确距离时一样。

- **要绕路的起点崩了，同一起点配对显著**：无坑时要绕路的 51 个起点，不给距离走到 32 个，换成直线距离只剩 20 个；有 12 个起点只有不给距离时走到，反过来 0 个（配对符号检验 p≈0.0005）。坑画成墙时绕 4 步以上 20/76 → 3/76（20 对 3，p≈0.0005）。
- **它几乎是照着所给的数字走**：直线距离组每一步有 99% 选的是直线距离最小的方向；在"直线最近"和"真实最近"不是同一个方向的步里（无坑 284 步、坑成墙 1,318 步），它跟直线的分别是 277 步和 1,295 步，跟真实的只有 7 步和 19 步。成绩落在纯程序的范围附近（无坑 80，略低于"并列先挑来过少的"那版的 82–94；坑成墙 20，在 18–39 内）。
- **不给距离时，它自己九成多的步也是往直线最近的方向走**：第三轮不给距离的两组，95% 和 91% 的步选的是直线距离最小的方向；冲突步里跟直线 300/320、1,048/1,256。所以第三轮"越要绕越走不到"可以读成：它眼里的"眼前最好"大致就是直线方向，和真实最短路不一致的地方就栽。
- **预测没全中：不用绕路的起点也掉了。** 无坑 66/69 → 60/69（6 对 0，p≈0.03），坑成墙 16/21 → 10/21（6 对 0，p≈0.03），没有"接近满分"。原因是档位的定义：绕 0 步只说明存在一条一路朝终点的路，不说明每个岔口朝终点的方向都通；朝终点的两个方向一样近时选错一个，就进死胡同在里面来回。纯程序在这一档同样只有 64%–90%（无坑）、50%–52%（坑成墙）。
- **如实写明"这是不考虑墙的直线距离"，数字就不起作用了**：成绩和不给距离逐起点几乎一样（98/120，绕路起点 32/51 对 32/51，只有 1 对 1 个起点不同）。它不是见数字就追，而是按字段名理解这个数是什么；误导来自"标成离终点几步"的错数。
- **结论（限这套迷宫）**：它每步挑眼前看起来最好的方向：给它标成"离终点几步"的数，它就照这个数走；数是对的就全走到，换成不管墙的直线距离，要绕路的地方就和只会挑最小数的程序一样栽。不给数时，它自己九成多的步也是往直线最近的方向走。适用范围：只测了 6×6 迷宫、一个快照、取 `choice`；机制上只能说表现得像。
- **补测"失败历史 + 只按墙算的距离"组的程序基线**：同地图、同 12 图 × 2 次 × 5 局、步数上限 40，纯程序每步走所给距离最小的方向（24 种顺序、两种并列规则全遍历），不读历史、距离也不随踩坑更新，每局都一样：288 串全部每局踩坑，0/120。Jev 在同一组是 5/120，比程序多出来的这点来自它读失败历史避开已知坑，但避开后找不到绕路，48 局超时。
- **第三轮"已知坑当墙算距离"组的 72/72 也由纯程序复现**：同样的记坑、重算距离和踩坑反馈，把 Jev 换成"走距离最小的方向"，24 种顺序 × 12 图全部是踩坑、踩坑、通关、通关、通关，合计 72/120，和 Jev 一样。所以那条曲线是"外部程序记坑、算路，Jev 照着距离走"这套系统的成绩，不能算 Jev 读历史学会通关的证据。Jev 自己读记录的那点增量见第五轮。
- 请求量 8,188 次（含冒烟 9 局 226 次，冒烟局沿用进全量），$0.22；程序基线 0 请求。

### 第五轮：只删踩坑记录的对照（`exp_icl_maze5.py`）

和第三轮"已知坑当墙算距离"组完全相同（同 12 图 × 2 次 × 连打 5 局，步数上限 40，程序照样记坑、当墙算步数，坑那一格照样显示走不通），唯一差别是 state 里不写前几局的踩坑记录。

| | 第 1 局 | 第 2 局 | 第 3 局 | 第 4 局 | 第 5 局 | 合计 | 第 2 局起重踩已知坑 |
|---|---|---|---|---|---|---|---|
| 有记录（第三轮） | 0/24 | 0/24 | 24/24 | 24/24 | 24/24 | 72/120 | 0/96 |
| 删掉记录（本轮） | 0/24 | 0/24 | 19/24 | 20/24 | 21/24 | 60/120（按图 39%–61%） | 12/96 |

- **删掉记录会掉，但主力仍是程序**：没有记录时，它偶尔会走进程序标着"走不通"、类型仍写空地的已知坑，有记录时这 12 次全躲开了。纯程序照步数走是 72/120（第四轮末条），所以 Jev 没有记录时反而不如纯程序；记录的作用是让它照程序标的"走不通"办。要是程序把坑直接标成墙，就用不着读记录（单局"坑画成墙 + 正确距离"120/120）。
- 两组按局号配对、到第一次分岔为止的步子，方向 92% 一致（757/819）；有 1 局在第 1 局就分岔（两组第 1 局 state 相同），说明同一 state 下 Jev 的选择也不是严格确定的。
- 请求量 1,246 次（含冒烟 1 局），$0.036。

## 五、国际象棋：认得出同局面的旧错，没看到迁移（`exp_icl_chess.py`，首轮）

（下棋不是本专题重点，只做了首轮。）

**设计。** 取[国际象棋实测](../games/chess/README.md#五换个问法也改不动棋力)问法对比里 Jev 送过子的 38 个局面（比两层物质搜索最好一步差 ≥2 分、且走完自己亏 ≥2 分），"错误"就是它当时那步。请求沿用原来的接法（选项是带 `#`/`+`/`x` 的 SAN），state 另加一个 `past_experience`。每局面每写法 2 次，每格 76 题。别处局面的记录取自随机局面的送子负例，没有控制战术相似，也没有同类局面的正负成对示例。

| 写法 | 重走那步错着 | 送子 | 选中最好一步 | 平均比最好差几分 | 输入 token 中位 |
|---|---|---|---|---|---|
| base 不给记录 | 56 | 60 | 15 | 2.99 | 1,074 |
| rec1 同局面一条错误记录（走了 X，对方 Y 吃回，净亏 k） | 21 | 39 | 34 | 1.79 | 1,177 |
| lesson 程序写"这个局面 X 是送子，别走" | 0 | 32 | 39 | 1.79 | 1,153 |
| note 把记录写进 X 那个选项的描述 | 0 | 32 | 40 | 1.74 | 1,098 |
| mix 错误记录 + 同局面一条"走 Z 没丢子、这步不错" | 0 | **0** | **76** | 0.00 | 1,268 |
| other10 只给 10 条别的局面的送子记录 | 54 | 60 | 14 | 2.86 | 2,059 |
| other60 60 条 | 54 | 58 | 15 | 2.87 | 6,944 |
| other250 250 条 | 50 | 57 | 17 | 2.70 | 25,478 |
| buried 本局面那条夹在 250 条中间 | 43 | 53 | 20 | 2.36 | 25,551 |

（"平均差几分"把将杀的 999 截到 20。）

- **同一局面记过的错着，它明显少走**（56 → 21，仍有 21/76 重走；由程序写成结论或标到选项上时是 0）。但排除那步后仍有 32/76 换一步照样送子。
- **记录里写着哪步好，它就照抄**（mix 76/76 选中最好一步）：只对一模一样的局面有效。
- **别处局面的教训没见迁移**：在这些局面和这种随机负例记录下，10、60、250 条别处的送子记录（最多约 2.5 万 token），送子 60 → 57。更相关、写得更清楚的示例是否有效，没测。
- 250 条里找本局面那条只找回一部分（重走 43/76，单独给时 21/76）。

**上下文容量是不是主因？** 本实验没触及容量上限（250 条约 2.5 万 token，没到 32K），加长也没看到收益；查表这条路一条局面记录约 100 token，32K 只装得下约 300 个局面，数量级上就不够。但没有排除写法、有效上下文利用和经验相关性的影响。

## 口径与未覆盖

- 只测一个快照、OpenRouter 一个入口。每格样本见各表（首轮 30 或 76 题、迷宫 24 轮；补测 50 / 100 / 150 题、老虎机 40 局、迷宫 24 轮；老虎机第四轮每组 160 局）。30 题的格子 95% 区间很宽（如 18/30 约 42%–75%），差几题别当差别读；在线老虎机 40 局、迷宫 12 张图，请求数多不等于独立样本多；这两项的比例区间按局 / 按图算，第 1 局单独统计、首轮各表仍是按题的 Wilson 区间。
- 重复样本不等于独立样本：国际象棋每个局面问 2 次，84% 的重复给出同一步，每格 76 题实际约相当于 38–45 个独立样本；迷宫不给历史的条件多数是同一条轨迹重复（首轮 7/8 张图，补测两组 10/12、9/12 张图），这些组的局数也不是独立样本（有历史的组轨迹会分叉，补测和第三轮的区间已按图算）。Jev 对同一 state 选的项基本不变，但概率有抖动：补测里同一 state 的第一步，56% 的重复给出的概率不一样。
- 首轮老虎机在线部分和首轮迷宫的日志没存 model 与用量，"全部经该快照"对这两块是按请求参数推定的；其余日志里记了 model 的条目都是 `typesafe/jev-1.13-20260917`。
- 首轮不同历史长度重新生成了任务和测试牌，长度之间不是同一条历史变长；补测猜规则改成了同一序列的前缀。补测老虎机固定历史仍按长度各自生成。
- 老虎机测了 4 臂 0.75/0.25、8 臂 0.75/0.25、4 臂 0.6/0.5 三种（后两种在第三轮，只测了原问法；第四轮换新奖励种子复测了 8 钮原问法和 4 钮三种问法）；规则只有单特征规则；迷宫只有 6×6、两个陷阱；国际象棋只测了原接法和 38 个送子局面。
- 补测里中英对照只做了猜规则全部写法和老虎机固定历史两种写法；在线老虎机、迷宫仍只用中文。
- 抽样用的是回包里两位小数的概率；没有试温度、只在头几名里抽等其它抽样法。
- 没有拿别的模型（包括生成式大模型）跑同一套老虎机、迷宫做对照；和文献的比较只是旁证。
